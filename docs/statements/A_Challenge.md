# A. Adaptive Puzzle Solving Challenge

## Краткое описание

В этом соревновании требуется разработать универсальный алгоритм для решения обратимых дискретных головоломок.

Каждая головоломка задается в виде `gym.py`-среды с единым интерфейсом:

- есть состояние;
- есть набор допустимых действий;
- действия переводят состояние в новое состояние;
- все действия обратимы;
- есть известное целевое собранное состояние;
- задача - найти последовательность действий, переводящую начальное состояние в целевое.

Участник отправляет код решения и, при желании, веса предобученной модели.

На стороне проверяющей системы решение запускается на скрытых головоломках и тестовых состояниях. GPU не используется: все решения запускаются на 8 ядрах CPU.

Главная идея соревнования - проверить не решение под одну конкретную игру, а общий подход к решению целого класса головоломок.

## Бейзлайн

Базовый пример решения и визуализацию открытых сред можно скачать архивом по ссылке, указанной организаторами.

## Основная идея

В открытой части предоставляются примеры нескольких головоломок и базовое решение. Однако при расчете итоговых оценок используются другие головоломки, неизвестные участникам заранее. Это справедливо и для публичного, и для приватного лидерборда.

Приватные и публичные проверочные головоломки следуют тому же общему формату:

- тот же `gym.py` API;
- те же типы ячеек;
- те же типы действий;
- тот же формат представления состояния и действий;
- не появляются новые форматы данных, неожиданные типы объектов или несовместимые дескрипторы действий.

Новые скрытые задачи не требуют переработки протокола. Они требуют обобщающего алгоритма, способного адаптироваться к новой головоломке, заданной через общий Gym-интерфейс.

## Какие головоломки рассматриваются

Все головоломки относятся к классу дискретных обратимых задач планирования.

Для них характерно:

- состояние состоит из набора дискретных ячеек;
- в ячейках находятся числа, цвета, пустоты или маскированные значения;
- есть фиксированное целевое состояние;
- действия не разрушают поле и не создают новые элементы;
- действия являются обратимыми;
- действия обычно являются перестановками, обменами, вращениями или переключениями;
- задача состоит в поиске короткой последовательности действий до цели.

Примеры действий:

| Тип действия | Описание |
|---|---|
| `SWAP` | Обмен содержимого нескольких ячеек |
| `ROTATE` | Циклический сдвиг строки, слоя, кольца или уровня |
| `TOGGLE` | Переключение значений в выбранных ячейках |
| `PERMUTE` | Более общая перестановка содержимого набора ячеек |

В задачах нет необратимых действий, разрушения поля, скрытых стохастических эффектов или непрерывного управления.

## Формат состояния

Состояние головоломки описывается через унифицированное представление.

Каждая ячейка имеет:

- позицию в 3D-координатах;
- тип текущего содержимого;
- числовое значение текущего содержимого;
- тип целевого содержимого;
- числовое значение целевого содержимого.

Типы содержимого фиксированы:

| Тип | Описание |
|---|---|
| `NUM` | Числовая фишка или уникальный объект |
| `COLOR` | Цветной объект, где объекты одного цвета взаимозаменяемы |
| `EMPTY` | Пустая ячейка |
| `MASKED` | Маскированная или несущественная ячейка |

Для всех hidden-задач используются те же типы.

## Формат действий

Каждое действие имеет унифицированное описание.

Действие содержит:

- тип действия;
- ось, вдоль которой оно действует, если применимо;
- направление;
- список затронутых ячеек;
- отображение `map_from` / `map_to`, если действие является перестановкой содержимого.

Типы действий фиксированы:

- `SWAP`;
- `ROTATE`;
- `TOGGLE`;
- `PERMUTE`.

В скрытых задачах не появляются новые типы действий.

## Открытые примеры для обучения

Для обучения, отладки и локальных экспериментов предоставляются примеры трех головоломок.

### Игра "15"

- классическая головоломка с пустой клеткой;
- действие меняет местами пустую клетку и соседнюю фишку.

### Выключение лампочек в матрице

- бинарная матрица;
- действие переключает выбранную лампочку и ее соседей.

### Цилиндр с шариками "Варикон"

- цилиндрическая головоломка с цветными шариками;
- уровни цилиндра можно вращать;
- шарики можно перемещать через одну верхнюю свободную ячейку.

Также предоставляется baseline-код, демонстрирующий:

- как импортировать `gym.py`;
- как использовать представления состояния и действий;
- как запускать обучение;
- как формировать `submission.csv`;
- как использовать простой RL-подобный ранжировщик действий и beam search.

## Формат ввода

Участник отправляет папку с решением, содержащую как минимум:

```text
train.py    # код дообучения модели
solve.py    # код для применения модели для решения головоломок
```

Опционально:

```text
model.pt    # веса модели
другие файлы, используемые в решении
```

В систему нужно отправлять zip-архив со всеми файлами.

## Формат вывода

### Роль `train.py`

`train.py` запускается проверяющей системой отдельно для каждой скрытой головоломки.

Во время запуска `train.py` в рабочей директории доступен соответствующий `gym.py`.

Участник может:

- импортировать `gym.py`;
- взаимодействовать со средой;
- генерировать собственные scramble-состояния;
- обучать модель с нуля;
- дообучать предобученную модель;
- сохранять веса и вспомогательные файлы в рабочую директорию.

На обучение выделяется 50 минут для каждого `gym.py`.

### Роль `solve.py`

После `train.py` запускается `solve.py`.

Во время запуска `solve.py` доступны:

- `gym.py`;
- `input_states.jsonl` - набор стартовых состояний для данной головоломки.

`solve.py` должен создать файл `output_actions.csv`.

Формат CSV:

```csv
instance_id,actions
example_000001,ACTION_1 ACTION_2 ACTION_3
example_000002,
example_000003,ACTION_4 ACTION_7
```

Где:

- `instance_id` - идентификатор тестового состояния;
- `actions` - последовательность действий через пробел;
- пустая строка означает, что решение для данного состояния не найдено.

На решение выделяется 25 минут на 1000 примеров публичной и приватной части.

## Система оценивания

### Публичный и приватный наборы данных

Для каждой проверочной головоломки подготовлены два набора состояний: публичный и приватный. Участники не получают эти состояния заранее.

Во время публичной оценки `solve.py` получает только публичный набор, смонтированный как `input_states.jsonl`. Во время оценки приватной части `solve.py` аналогично получает приватный набор под тем же именем.

Сам `solve.py` не знает, публичная это часть или приватная. Разбиение полностью контролируется проверяющей системой.

### Оценка на публичной части

Публичный набор содержит 300 примеров. Публичная оценка используется для отображения текущего качества на лидерборде.

### Оценка на приватной части

Приватный набор содержит 700 примеров. Он имеет аналогичную сложность и генерируется тем же способом, что и публичный набор.

На прогон на публичном и приватном наборе суммарно дается 25 минут.

Оценка на приватной части используется для финального ранжирования.

### Независимость запусков

Запуски на разных головоломках полностью независимы:

- для каждой hidden-головоломки запускается отдельный `gym.py`;
- `train.py` и `solve.py` работают только с одной текущей средой;
- решение не может одновременно дообучаться на нескольких скрытых `gym.py`;
- рабочие директории разных запусков физически разделены;
- файлы, созданные при обучении на одной головоломке, не доступны при обучении на другой.

Участник может использовать общий предобученный подход, но адаптация во время проверки происходит отдельно для каждой задачи.

## Метрика

Для каждого тестового состояния известно базовое решение, полученное при генерации состояния random walk из решенного состояния.

Пусть:

- `baseline_length` - длина базового решения;
- `moves` - длина решения участника.

Если решение корректно и приводит к целевому состоянию, оценка для состояния:

```text
score = baseline_length / moves
```

Если решение невалидно, отсутствует или не приводит к цели, оценка равна `0`.

Итоговая оценка по набору - среднее значение по всем состояниям. Итоговая оценка по нескольким головоломкам агрегируется проверяющей системой.

## Примечание

Ожидается, что участники будут разрабатывать не набор ручных решений под конкретные игры, а общий алгоритм, достаточно адаптивный для работы с неизвестными головоломками, ограниченным временем инференса и независимыми запусками.

Возможные подходы:

- предобучение универсальных моделей;
- reinforcement learning;
- MCTS;
- imitation learning;
- другие адаптивные методы поиска и ранжирования действий.
