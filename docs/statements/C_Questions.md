# C. Effective Inference On School Questions

## Описание задачи

Типичные школьные вопросы уже хорошо решаются большими LLM:

- "разобрать слово по составу";
- "сколько будет 3/4 + 7/8";
- "сочинение про осень";
- "уравнение реакции Fe + HNO3";
- "how to use Present Perfect".

Но запускать огромную модель на каждый такой запрос дорого и медленно. Ответ нужен быстро, а вычислительный бюджет ограничен.

Задача контеста - научить маленькую модель отвечать на школьные вопросы так же хорошо, как большая. Модель должна уложиться в ограничения по времени и ресурсам: быть не только качественной, но и быстрой.

Для дообучения предоставляется обучающая таблица со школьными запросами и качественными ответами. Также доступен архив с базовым решением.

## Формат ввода

Решение представляет собой Docker-контейнер. Проверяющая система:

1. запускает контейнер;
2. подкладывает файл с вопросами;
3. ожидает файл с ответами.

В задачу нужно прислать zip-архив с решением.

## Содержимое zip-архива

Минимальная структура:

```text
Dockerfile        # описывает окружение
solution.py       # точка входа, запускается при старте контейнера
weights/          # веса вашей модели
├── config.json
├── tokenizer.json
├── model.safetensors
└── ...
```

Можно добавлять любые свои файлы:

- скрипты;
- дополнительные данные;
- еще одну модель;
- вспомогательные конфиги.

Все, что попадет в zip, окажется в папке `/workspace` внутри контейнера.

## Как правильно собрать архив

### Лучший вариант

Плоский архив:

```text
Dockerfile
solution.py
weights/
```

Файлы лежат прямо в корне zip-файла, без оберточной папки. Именно так устроен скачанный шаблон: нужно выделить все файлы внутри папки и упаковать их.

### Допустимый вариант

Одна оберточная папка:

```text
my-solution/
├── Dockerfile
├── solution.py
└── weights/
```

Система автоматически поднимет содержимое этой папки наверх. Такой вариант часто получается на macOS при упаковке через "правый клик -> Сжать".

### Недопустимый вариант

Двойная обертка:

```text
my-solution/
└── my-solution/
    ├── Dockerfile
    ├── solution.py
    └── weights/
```

В этом случае система не сможет корректно найти файлы, и посылка получит `PresentationError`.

## Файл с вопросами: `input.pickle`

Файл `/workspace/input.pickle` - это Python pickle со списком словарей:

```python
[
    {"rid": 1, "question": "..."},
    {"rid": 2, "question": "..."},
    ...
]
```

Поля:

| Поле | Описание |
|---|---|
| `rid` | Уникальный номер вопроса |
| `question` | Сам вопрос школьника |

Пример лежит рядом с бейзлайном: `example-dataset.pickle`.

## Формат вывода

Ваш код должен положить в `/workspace/output.json` JSON-список:

```json
[
  {"rid": 1, "answer": "..."},
  {"rid": 2, "answer": "..."}
]
```

Правила:

- `rid` должен совпадать с тем, что пришел во входе;
- `answer` - текст ответа вашей модели;
- на каждый `rid` из входа должен быть ровно один `answer` в выходе;
- лишних `rid` быть не должно;
- если ответа нет, лучше вернуть пустую строку, чем пропустить вопрос.

## Система оценивания

Качество ответов оценивает отдельная модель-судья. Она обучена ставить высокий балл хорошим ответам и низкий - плохим.

Процесс оценки:

1. решение получает вопросы;
2. решение выдает ответы;
3. модель-судья присваивает каждому ответу скор;
4. скоры усредняются;
5. среднее значение становится итоговым баллом.

## С чего начать

Организаторы предоставляют архив, в котором уже есть рабочий пример решения:

- `solution.py`;
- `Dockerfile`;
- `download_weights.py`;
- `example-dataset.pickle`.

Базовый порядок действий:

1. Установить Docker.
2. Скачать веса модели-бейзлайна в папку `./weights`.
3. Собрать и прогнать решение на примере.

```bash
docker build -t my-solution .
mkdir -p out
docker run --rm --gpus all \
  -v "$PWD/example-dataset.pickle":/workspace/input.pickle \
  -v "$PWD/out":/workspace/out \
  my-solution
cat out/output.json
```

После проверки нужно упаковать содержимое папки в zip, включая `weights/`, и загрузить на `contest.yandex.ru`.

## Бейзлайн: vLLM + Qwen3-0.6B

В архиве уже есть рабочее решение:

- поднимает движок инференса `vLLM`;
- использует маленькую модель `Qwen3-0.6B`;
- прогоняет через нее все вопросы из `input.pickle`;
- записывает ответы в `output.json`.

В бейзлайне нет специального промпта или дополнительных трюков. Это нижняя планка, с которой удобно сравнивать улучшения.

Этого достаточно, чтобы отправить первое решение и увидеть свой балл.

## Подготовка весов

Один раз локально нужно запустить:

```bash
python download_weights.py
```

Скрипт положит веса `Qwen3-0.6B` размером примерно 1.2 ГБ в папку `./weights`.

Папку `weights/` нужно включить в zip-архив. Без весов контейнер внутри контеста не сможет ничего скачать, потому что сети нет.

## Данные для обучения

Для дообучения предоставляется обучающая таблица: 10 тысяч строк с реальными школьными запросами.

Каждая строка содержит два поля:

| Поле | Описание |
|---|---|
| `query` | Текст запроса школьника, тот же формат, что и `question` в `input.pickle` |
| `answer` | Эталонный ответ на этот вопрос |

Файл лежит в формате `.parquet` и читается так:

```python
import pandas as pd

df = pd.read_parquet("train.parquet", engine="pyarrow")
```

Для чтения нужен `pyarrow`:

```bash
pip install pyarrow
```

Использовать эти данные не обязательно. Можно решать задачу промптами, дообучением, дистилляцией или другим способом.

## Ограничения

- Контейнер запускается без доступа к интернету.
- Все нужное - веса моделей, пакеты, данные - должно лежать в образе или архиве.
- Скачать что-либо на лету не получится.
- Время генерации ответов на 4000 запросов должно быть менее 15 минут.
- Размер образа должен быть менее 20 ГБ.
- Размер посылки должен быть менее 10 ГБ.
- Решение запускается на сервере с одной видеокартой L4.
- Доступно 4 попытки раз в 24 часа.
